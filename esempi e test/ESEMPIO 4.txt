⚠️ Un problema strutturale rimasto
Il Plan Mode è sepolto come step 7 di una lista numerata di azioni.
Questo è pericoloso: Claude legge la lista come una sequenza di passi da eseguire. Al passo 7 trova "NON iniziare l'esecuzione finché il piano non è approvato" — ma i passi 1–6 sono già stati letti come istruzioni operative. Un agente potrebbe ragionevolmente concludere che la sequenza sia: esegui 1-6, poi al passo 7 presenta il piano. Oppure potrebbe ignorare il conflitto e procedere.
Soluzione: Il Plan Mode deve essere una sezione autonoma, prima delle Istruzioni, come già facevi nella v2 (quella era corretta su questo punto):
## Piano di Esecuzione
Dopo aver letto tutte le istruzioni, presenta un piano 
numerato. NON eseguire alcun comando prima dell'approvazione.

## Istruzioni
1. Safety & Branching
2. Directory e File Creation
...

⚠️ Un problema minore
"o un file simile" nel contesto crea un'ambiguità non gestita:

docs/index.md (o un file simile che funge da punto di ingresso)

Se il file non si chiama esattamente docs/index.md, il str_replace al passo 4 fallirà senza recovery. Aggiungi una fallback instruction tipo: "Se docs/index.md non esiste, cerca il file indice nella directory docs/ prima di procedere."
