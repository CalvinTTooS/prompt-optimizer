⚠️ Problemi da correggere
1. La regola "Dynamic Generation (NO BASH CAT)" è controproducente
È il punto più critico. Vietare cat << EOF e sostituirlo con python -c "print(...)" è in realtà peggio, perché:

Claude Code ha tool nativi (write_file / str_replace) — li usa già in modo intelligente, non hardcoda nulla in bash
Forzare python -c per file multi-linea genera bash illeggibile e fragile
La regola nasce da un'incomprensione: in Claude Code il "contenuto generato intelligentemente" arriva dai tool di editing, non dalla shell

Soluzione: Rimuovi questa regola. Al massimo puoi scrivere: "Usa i tool nativi di scrittura file, non heredoc bash."

2. I link markdown sono mal formati
Nel testo compaiono [README.md](http://README.md), [main.py](http://main.py), [CLAUDE.md](http://CLAUDE.md) — sembrano generati da Notion o simili che auto-linka i nomi file. Claude Code li interpreterà correttamente, ma è rumore e potenzialmente confuso. Usa direttamente i path grezzi: `README.md`, `src/main.py`.

3. L'attivazione del virtualenv non persiste tra i tool call
Claude Code esegue ogni comando bash in una subshell separata, quindi source venv/bin/activate non ha effetto sui comandi successivi. Le istruzioni non lo contemplano.
Soluzione: Specificare esplicitamente di usare venv/bin/pip e venv/bin/python nei comandi successivi, oppure consigliare uv che gestisce l'ambiente implicitamente.

4. "Plan Mode → Esegui passo dopo passo" è ambiguo
In Claude Code il Plan Mode significa: Claude presenta il piano, l'utente approva, poi si esegue. Il tuo prompt dice di generare il piano E poi eseguirlo nello stesso turno — questo bypassa l'approvazione umana, che potrebbe essere intenzionale o no. Chiarisci se vuoi:

Solo il piano (da approvare prima di eseguire)
Piano + esecuzione immediata in autonomia
